# FRAME ATLAS 2.0 (초기 개발본)

현재 개발 브랜치: \`v2-development\`  
작업 경로: \`v2/\`  
목표: 서울·수도권을 시작점으로 삼아 촬영 로케이션과 대표사진을 체계적으로 조사·검증하는 새 앱을 만든다.

## 지금 들어간 기능

- 서울·경기·인천의 초기 장소 후보 24곳. 이 목록은 시작용이며 주소·운영·촬영 허가·이미지는 아직 일괄 검증되지 않았다.
- 장소별로 Google 이미지, Bing 이미지, 네이버 이미지, 다음 이미지, Flickr, Openverse, Wikimedia Commons, 공식·관광 출처 검색을 여는 링크.
- 앱 안에서 Openverse 및 Wikimedia Commons의 이미지 검색 결과를 가져와 후보로 저장.
- 후보별 이미지 주소, 원본 페이지, 사이트/작가, 라이선스, 권리 근거, 실제 장소 일치 여부, 사진 구도 및 메모 기록.
- 출처와 권리 상태를 조건으로 대표사진 승인을 제한.
- 장소 및 후보 데이터를 JSON으로 내보내고 가져오는 기능.
- 모바일 화면에 맞춘 장소 목록·검색·사진 후보 검토 화면.

## 핵심 개발 원칙

1. **이미지 발견량과 사진 정확도를 함께 높인다.** 자동 검색은 가능한 한 폭넓게 하되 검색 결과를 곧바로 대표사진으로 등록하지 않는다.
2. **장소 일치와 사용 권리를 별개로 기록한다.** 사진이 맞는 장소를 보여준다고 해도 공개 재사용 권리가 자동으로 생기지 않는다.
3. **항공사진·홍보 포스터·지도 이미지를 실제 현장 대표사진과 구분한다.** 후보에 촬영 구도를 기록하고 필요하면 제외한다.
4. **원본을 덮어쓰지 않는다.** 현재 v5.x 앱과 데이터는 유지한다. 2.0은 별도 경로에서 개발한다.
5. **공통 카탈로그와 개인 메모는 다르게 취급한다.** 현재 2.0은 개인 메모·복잡한 기기 동기화를 필수로 만들지 않고, 장소·이미지 카탈로그를 안정화하는 데 집중한다.

## 알려진 제한

- Google/Bing/Naver/Daum/Flickr 페이지는 외부 검색으로 연다. 검색 결과 페이지를 무단으로 긁어오지 않는다. 해당 엔진의 공식 API/권한이 없는 상태에서 자동 수집을 약속하지 않는다.
- Openverse와 Commons API는 검색 후보를 자동으로 제공할 뿐, 실제 장소 일치·권리·최신성을 보증하지 않는다.
- 브라우저에서 수정한 초안은 현재 사용 기기에 저장된다. 다른 기기에 나타나게 하려면 아직은 JSON 내보내기 후 배포용 카탈로그에 게시하는 단계가 필요하다. 안전한 게시 기능은 다음 단계에서 설계한다.
- 웹 이미지의 URL을 등록하는 것은 파일을 영구 보관하는 것과 다르다. 핫링크 차단, 삭제, 주소 변경에 대비해 공개 재사용 권리가 확인된 사진은 추후 저장소 내 파일로 보관하는 기능을 추가한다.
- 저장소가 공개라면 그 안에 두는 사진과 장소 정보는 누구나 볼 수 있다. 공개 사용 권리가 확인되지 않은 이미지를 저장소에 복제하지 않는다.

## 다음 단계

1. 기존 v5.x 데이터에서 장소명·별칭을 회수해 중복을 제거하고 이 후보 목록에 병합한다.
2. 실제 검색 결과 수집, 사진 후보의 장소 일치 검토, 출처/라이선스 검증 워크플로를 점검한다.
3. 안전한 공통 카탈로그 게시 흐름을 만들어 PC에서 확정한 내용이 모바일의 배포 버전에 반영되도록 한다.
4. 장소 정보와 이미지 출처를 실제 확인하며 우선순위 높은 장소부터 채운다.
5. 자동 검사와 PC/iPhone 검증을 통과한 후에만 운영 경로로 옮긴다.
