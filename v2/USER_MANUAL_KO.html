먼저 알아둘 핵심

  1. 최신 2.0 주소로 열기. FRAME ATLAS 2.0 열기. 주소에 /v2/index.html이 있어야 합니다.
  2. 관리자 모드가 있어야 편집할 수 있습니다. 새 장소 등록, 수정, 삭제, 사진 변경 및 게시 기능은 관리자 잠금 해제 후 이용합니다.
  3. 저장과 게시를 구분하세요. ‘이 기기에 임시저장’은 현재 브라우저의 초안입니다. 다른 기기로 전달하려면 백업 후 GitHub 게시와 배포를 확인해야 합니다.
  4. 사진 일치·저작권·촬영 허가는 서로 별개입니다. 방문이 가능해도 상업 촬영이나 사진 재사용이 허용된다는 뜻은 아닙니다.
안전: 중요한 편집 전후로 JSON 백업을 다운로드하세요. 브라우저 데이터 삭제, 기기 변경, 초안 초기화로 임시 자료를 잃을 수 있습니다.

가족용 빠른 시작: 설치 → 장소 → 메모 → 공통 게시

먼저 구분하세요. 가족이 앱을 열어 장소를 보는 것은 누구나 할 수 있지만, 새 장소 등록·수정·삭제는 관리자 모드가 필요합니다. 입력 후 ‘이 기기에 임시저장’된 내용은 자동으로 다른 가족의 기기에 전송되지 않습니다.

A. iPhone 홈 화면에 앱 아이콘 만들기

  1. iPhone에서 Safari로 FRAME ATLAS 주소를 엽니다. 카카오톡 등 앱 내부 브라우저로 열렸다면 Safari에서 다시 엽니다.
  2. Safari의 공유 버튼(네모에서 위쪽 화살표)을 누릅니다.
  3. 목록에서 홈 화면에 추가를 선택합니다. 안 보이면 아래쪽의 ‘동작 편집’에서 추가합니다.
  4. ‘웹 앱으로 열기’가 표시되면 켜고 ‘추가’를 누릅니다. 홈 화면에 FRAME ATLAS 아이콘이 생깁니다.
  5. 처음 실행할 때 인터넷에 연결하고, 시작 화면에서 ‘시작하기’ 또는 홈 이동 버튼을 누릅니다.

중요: 홈 화면 아이콘 앱과 Safari에서 직접 연 페이지는 저장 공간이 다를 수 있습니다. 메모를 남길 때는 주로 사용할 한 가지 방식으로 계속 이용하세요. Apple 공식 안내: iPhone에서 웹사이트를 앱처럼 열기.

B. 장소를 찾고 상세 메모 기록하기

  1. 홈의 검색창에 장소명·지역·키워드를 입력하거나 지역/공간 유형 필터를 선택합니다.
  2. 장소 카드를 눌러 상세 화면을 엽니다. 주소, 사진, 운영 조건과 촬영 가능 표시는 참고 자료이므로 촬영 전에 공식 운영처에서 다시 확인합니다.
  3. 상세 화면 아래의 현장 촬영 체크리스트에 빛 방향, 촬영 포인트, 주차·장비 반입, 전력, 탈의·대기 공간, 혼잡도, 현장 답사 내용을 기록합니다.
  4. 현장 체크리스트 저장을 누르고 저장 완료 문구를 확인합니다. ‘이 기기에 저장’이라고 표시되면 현재 기기에 저장된 것이며 가족에게 자동 공유된 것이 아닙니다.
  5. 관리자 모드에서 장소 기본 정보나 ‘촬영 기획·분류 정보’를 수정했다면 해당 영역의 저장 버튼도 각각 눌러야 합니다.

C. 새 장소 등록하기 (편집 권한이 있는 사용자)

  1. 마이페이지에서 관리자 모드를 누르고 앱 관리자가 별도로 안내한 관리자 비밀번호를 입력합니다. 모드 잠금은 화면의 실수 방지 장치이며 서버 로그인 기능은 아닙니다.
  2. 홈 또는 목록에서 ＋ 장소 신규 등록 또는 ＋ 새 장소 등록을 누릅니다.
  3. 장소 이름, 지역, 공간 유형, 주소 또는 지도 검색어부터 입력합니다. 같은 이름·주소를 검색해 중복 등록을 피합니다.
  4. 기본 정보 저장 버튼을 누릅니다. 이어서 촬영 기획·분류 정보에 사진가 관점의 특징, 빛·재료·구도, 추천 콘셉트, 제약 조건, 출처 URL, 추가 메모를 입력하고 별도로 저장합니다.
  5. 현장 체크리스트와 세부 메모를 입력하고 해당 저장 버튼을 누릅니다. 사진·비용·좌표·허가를 실제 확인하지 않았다면 ‘미확인’으로 남깁니다.

D. 새 장소와 메모를 모든 기기의 공통 목록에 게시하기

  1. 게시 전 안전 백업 내보내기로 JSON 파일을 저장합니다. 중요한 대량 수정 전후에는 별도 파일명으로 백업을 남깁니다.
  2. 관리자 모드에서 GitHub 동기화·게시를 엽니다. 게시 담당자가 보유한 GitHub 쓰기 토큰을 입력하고 ‘동기화 시작’을 누릅니다.
  3. 토큰 기억 옵션은 게시 담당자 본인의 기기에서만 사용합니다. 가족 공용 기기나 공공 PC에는 토큰을 저장하지 마세요.
  4. 게시 결과 메시지를 확인합니다. 같은 장소의 같은 항목이 서로 다르게 수정되면 충돌로 인해 게시가 중지될 수 있으므로, 백업 후 해당 값을 정리하고 다시 게시합니다.
  5. GitHub 저장소의 Actions에서 Pages 배포 성공을 확인한 후, 다른 기기에서 앱을 새로고침하거나 완전히 종료한 뒤 다시 엽니다. 새 장소명·메모·사진이 실제로 보이는지 확인합니다.
보안·공개 범위: GitHub 토큰은 게시 권한이 있는 비밀 정보이므로 가족 단체방이나 매뉴얼에 공유하지 마세요. 공통 카탈로그에 게시한 장소 설명과 메모는 공개 웹사이트 방문자에게도 보일 수 있습니다. 가족 연락처, 비밀번호, 사적인 대화 같은 내용을 공통 장소 메모에 적지 마세요. 가족별 비공개 메모를 자동 동기화하는 개인 계정 기능은 현재 제공되지 않습니다.

E. 권장 역할

  • 일반 가족 사용자: 공통 장소 보기·검색, 즐겨찾기 및 현장 메모를 사용합니다. 기기에만 남은 메모는 자동 동기화된 것으로 생각하지 않습니다.
  • 장소 편집·게시 담당자: 관리자 모드에서 장소 정보를 정리하고, 백업·GitHub 동기화·게시와 배포 확인을 수행합니다.

9. 백업·복원·GitHub 게시

수정 전 백업

  1. 관리자 도구에서 ‘안전 백업 내보내기’ 또는 ‘백업 내보내기’를 누릅니다.
  2. 다운로드한 JSON을 PC의 별도 폴더에도 보관합니다. 파일명에 날짜를 넣어 이전 상태와 구분합니다.
  3. 장소·사진을 많이 수정한 뒤에도 새 이름으로 추가 백업을 저장합니다.

백업 가져오기

‘JSON 백업 가져오기’는 현재 기기의 작업 카탈로그를 통째로 바꿀 수 있습니다. 가져오기 전에 현재 상태도 먼저 내보내세요. 오래된 기기 백업을 최신 공통 자료에 무심코 가져오면 다른 기기에서 게시한 수정사항을 덮어쓸 수 있으므로, 두 파일을 자동 병합하는 기능이라고 생각하면 안 됩니다.

GitHub 동기화·게시

  1. 첫 동기화 전에는 현재 기기의 ‘안전 백업 내보내기’로 JSON 백업을 만듭니다.
  2. 관리자 도구에서 ‘GitHub 동기화·게시’를 누릅니다. 저장소 casio8000/FRAME_ATLAS에만 Contents 읽기/쓰기 권한을 준 Fine-grained Personal Access Token을 입력합니다.
  3. ‘이 기기에 GitHub 토큰 기억하기’는 본인만 쓰는 기기에서 선택하면 됩니다. 선택하면 해당 브라우저에만 저장되고 다른 기기로 복사되지는 않습니다.
  4. ‘동기화 시작’을 누릅니다. 앱은 GitHub 최신 카탈로그와 이 기기의 변경사항을 병합합니다. 서로 다른 필드의 수정은 합치고 같은 필드 충돌은 안전하게 중지합니다.
  5. GitHub Actions의 Pages 배포 성공을 확인하고 PC·모바일에서 2.0 주소를 새로고침합니다.
초기 1회: 예전 기기 초안에는 병합 기준점이 없을 수 있습니다. 이 경우 첫 동기화에서는 오래된 삭제를 자동 적용하지 않습니다. 장소를 삭제해야 하면 첫 동기화 성공 후 최신 자료를 다시 읽어 삭제를 다시 진행하세요.

사진 파일 게시 조건

인터넷 이미지 URL은 주소를 참조할 뿐 저장소에 파일이 복사되는 것이 아닙니다. 기기에서 선택한 사진 파일도 처음에는 해당 브라우저의 임시 보관소에 있습니다. 현재 게시 과정은 대표사진·기본 참고사진으로 선택되었거나 승인된 파일을 업로드 대상으로 처리합니다. 게시 완료 후 실제 파일 경로와 앱의 사진 표시를 확인하세요.

토큰과 초기화 안전

토큰은 선택한 경우 이 기기의 브라우저 저장소에만 보관됩니다. 본인만 쓰는 기기에서만 저장하고 공용 PC에서는 체크하지 마세요. ‘배포된 기본자료 다시 읽기’는 이 기기의 미게시 초안을 지울 수 있으므로 실행 전 JSON 백업을 내보내세요.

11. PC·모바일 데이터 동기화 — 간편 병합 방식

권장 방식: 한 명을 공통 게시 담당자로 정합니다. 장소 추가·공통 설명 편집은 관리자 모드에서 작업하고, 작성한 기기에서 저장해야 합니다.
꼭 알아둘 제한: 각 기기의 메모는 게시 담당자 기기로 자동 전송되지 않습니다. 공통으로 공유할 메모는 담당자에게 전달해 담당자 기기에서 다시 입력·저장하세요. 오래된 JSON 백업을 곧바로 가져오면 최신 자료를 바꿀 수 있으니 주의합니다.

동기화는 이렇게 진행됩니다

게시 버튼은 다른 가족의 기기 내부 저장소를 원격으로 읽는 기능이 아닙니다. 공통 목록으로 올릴 내용이 게시 담당자 기기에 입력되어 있어야 합니다.

  1. 각 기기에서 장소 등록·수정: 장소명·지역·위치 정보와 간단한 사진가 관점 설명부터 저장합니다. 참고 이미지는 실제 장소와 맞는지 확인한 범위에서 넣으면 됩니다. 점수·비용·세부 체크리스트를 완벽하게 채우지 않아도 먼저 등록할 수 있습니다.
  2. 관리자 모드 → GitHub 동기화·게시: 게시 직전에 앱이 GitHub의 최신 카탈로그를 다시 읽습니다. PC가 추가한 장소가 모바일에 없더라도, 모바일에서 새로 추가한 다른 ID의 장소와 함께 병합해 게시합니다.
  3. 서로 다른 항목 수정은 함께 유지: 예를 들어 PC에서 장소 주소를 수정하고 모바일에서 같은 장소의 촬영 메모를 수정했다면, 서로 다른 필드이므로 가능한 범위에서 합칩니다. 새로 추가한 장소도 ID가 다르면 합쳐집니다.
  4. 같은 항목을 양쪽에서 다르게 수정하면 중지: 같은 장소의 같은 필드가 서로 다르면 앱이 덮어쓰지 않고 충돌을 알려줍니다. 메시지에 나온 장소를 한 기기에서 정리한 뒤 다시 동기화합니다.
  5. 최신 배포 확인: 동기화·게시 완료 후 GitHub Actions의 Pages 배포가 성공하면 다른 기기에서 2.0 페이지를 새로고침합니다. 캐시나 오래된 로컬 초안이 남으면 이전 화면이 보일 수 있습니다.

처음 한 번만 주의할 점 — 예전 초안

이전에 사용하던 기기의 초안에는 병합 기준 시점이 없을 수 있습니다. 처음 동기화하기 전에는 관리자 도구에서 JSON 백업을 내보내세요. 앱은 오래된 초안의 새 장소와 더 최신으로 보이는 변경을 보존하려고 하며, 다른 기기의 최신 내용과 확실히 구별할 수 없는 충돌은 게시를 중지합니다. 기준이 없던 초안의 삭제는 안전을 위해 첫 동기화에서 자동 적용하지 않습니다. 첫 동기화가 성공하면 이후에는 새 기준본을 저장해 변경을 비교합니다.

토큰과 메모의 공개 범위

‘이 기기에 GitHub 토큰 기억하기’는 게시 담당자 본인만 쓰는 기기에서만 선택합니다. 토큰은 저장소 내용을 바꿀 수 있는 비밀 정보이므로 다른 가족에게 전달하지 마세요. PC에 저장해도 iPhone으로 복사되지 않습니다. 공통 카탈로그에 게시된 설명·출처·현장 메모는 공개 웹사이트를 통해 다른 방문자에게도 노출될 수 있습니다. 비밀번호·연락처·가족 사정 등 비공개 정보는 기록하지 마세요. 이 앱에는 가족별 비공개 메모를 계정으로 자동 동기화하는 기능이 없습니다.

사진 파일의 기기 차이

이미지 URL과 이미지 후보 정보는 병합할 수 있지만, 아직 게시하지 않은 파일 자체는 원래 선택한 기기의 임시 보관소에 있습니다. 해당 파일을 게시하려면 파일을 선택했던 기기에서 동기화·게시하거나, 다른 기기에서 파일을 다시 선택해야 합니다.

대표·참고사진 수정웹에서 여러 이미지를 둘러보고, 실제 장소와 이미지가 맞는지 중심으로 고릅니다. 출처와 사진 설명은 나중에 보완할 수 있습니다.
장소 삭제삭제는 다른 기기에도 반영되는 변경입니다. 병합 기준이 이미 있는 기기에서 삭제하면 변경사항으로 기록됩니다. 이전 초안의 첫 동기화에서 삭제가 무시된 경우, 첫 게시 이후 최신 자료를 다시 읽고 삭제를 다시 실행하세요.
백업대량 추가·수정 전에 JSON 백업을 권장합니다. 백업은 복구용이며, 오래된 JSON을 최신 카탈로그 위에 통째로 가져오면 안 됩니다.
중요: 앱은 PC와 모바일 사이의 서로 다른 장소·필드 수정 병합을 지원하도록 개선되었습니다. 네트워크/권한 오류나 같은 필드 충돌 시 게시가 중지될 수 있습니다. 중요한 장소 묶음 작업 전후에는 백업을 보관하세요.

11. 문제 해결

PC와 아이폰의 장소 수가 다름 (예: PC 201곳 · 아이폰 200곳)

현재 공통 장소 목록은 200곳입니다. 기존 버전에서 PC에만 저장된 임시 장소나, 같은 장소가 다른 ID로 중복된 기록이 남으면 PC 숫자만 늘어날 수 있습니다. 최신 빌드에서는 PC 임시자료를 공통 목록과 대조하여 같은 장소는 정식 ID 하나로 합치고, 공통 목록에 없는 미게시 초안은 이 기기에 별도 보존해 공식 장소 수에서 분리합니다.

현재 배포 빌드 20261016-100: PC·모바일 앱 캐시를 새로 갱신하고, 201곳으로 계산될 수 있는 오래된 PC 임시 목록을 공통 200곳과 대조하는 수정이 포함되어 있습니다. 공통 목록에 없는 고유 초안은 삭제하지 않고 별도로 보존합니다.
  1. 앱을 새로고침하거나 홈 화면 앱을 완전히 닫았다 다시 엽니다.
  2. 상단 저장 상태에 ‘공통 장소 200곳’이 표시되는지 확인합니다. 미게시 초안이 남아 있으면 건수가 함께 표시됩니다.
  3. 미게시 초안은 바로 삭제하지 않습니다. 관리자 모드에서 JSON 내보내기를 하면 백업 파일의 localUnpublishedPlaces 항목에 포함됩니다. 공통 200곳 목록에는 자동 게시되지 않습니다.
  4. 숫자가 여전히 다르면 브라우저 데이터를 지우지 말고, 먼저 관리자 모드에서 JSON 백업을 보관합니다.

PC에 저장된 임시 수정사항은 PC에서만 존재할 수 있습니다. 공통 목록에 올리려면 관리자 모드에서 안전하게 게시해야 합니다. 미게시 초안의 분리는 데이터를 지우기 위한 조치가 아니라 공통 목록과 기기별 자료를 구분하기 위한 조치입니다.

PC에서 매뉴얼 ‘맨 위로’·‘닫기 ×’가 안 보임

이 개정판은 PC에서 오른쪽 위, 작은 화면에서는 오른쪽 아래에 버튼을 고정합니다. 매뉴얼 최신판 다시 열기를 사용합니다. 닫기는 새 탭을 닫을 수 있으면 닫고, 그렇지 않으면 이전 화면 또는 앱으로 돌아갑니다.

관리자 비밀번호 불일치

  • 예전에 이 PC에서 자체 등록했던 비밀번호는 이전 방식일 수 있습니다. 현재는 전달받은 공통 비밀번호 두 개만 사용합니다.
  • 대·소문자와 하이픈을 확인하고 앞뒤 공백을 제거합니다. 새로고침한 뒤 다시 입력합니다.

수정이 모바일에서 안 보임

  1. 작업한 기기에서 ‘임시저장’인지 ‘게시 완료’인지 확인합니다.
  2. 백업 후 GitHub에 게시합니다.
  3. Actions에서 Pages 배포 성공 여부를 확인합니다.
  4. PC는 Ctrl+F5, 모바일은 홈 화면 아이콘 대신 브라우저에서 직접 2.0 주소를 엽니다.

목록으로 돌아갈 때 엉뚱한 위치로 이동
