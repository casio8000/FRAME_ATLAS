USER GUIDE / LOCATION SCOUTING

사용자 매뉴얼

건축의 형태와 재료, 빛과 그림자, 배경의 깊이, 인물 촬영 활용도를 검토하는 촬영 장소 조사 도구입니다. PC는 조사·편집·백업, iPhone은 탐색·현장 확인 중심으로 이용하세요.

개정판 2026-10-15 · 새 장소 등록과 PC·모바일 사용 추가

먼저 알아둘 핵심

  1. 최신 2.0 주소로 열기. FRAME ATLAS 2.0 열기. 주소에 /v2/index.html이 있어야 합니다.
  2. 관리자 모드가 있어야 편집할 수 있습니다. 새 장소 등록, 수정, 삭제, 사진 변경 및 게시 기능은 관리자 잠금 해제 후 이용합니다.
  3. 저장과 게시를 구분하세요. ‘이 기기에 임시저장’은 현재 브라우저의 초안입니다. 다른 기기로 전달하려면 백업 후 GitHub 게시와 배포를 확인해야 합니다.
  4. 사진 일치·저작권·촬영 허가는 서로 별개입니다. 방문이 가능해도 상업 촬영이나 사진 재사용이 허용된다는 뜻은 아닙니다.
안전: 중요한 편집 전후로 JSON 백업을 다운로드하세요. 브라우저 데이터 삭제, 기기 변경, 초안 초기화로 임시 자료를 잃을 수 있습니다.

1. 화면과 메뉴

화면용도·주의점
홈 / 전체 촬영 장소추천과 전체 장소를 검색하고 지역·공간 유형·촬영 분위기로 좁힙니다.
지도선택한 장소의 지도·길찾기를 엽니다. 핀보다 정확한 주소와 실제 출입구를 다시 확인하세요.
저장 장소하트/저장하기로 즐겨찾기에 추가합니다. 개인 즐겨찾기는 현재 브라우저에 저장되며 기기 간 자동 동기화되지 않을 수 있습니다.
사진 후보 / 내 갤러리후보 사진과 장소 일치 상태를 비교합니다. ‘확인 필요’나 ‘다른 장소 사진’은 확정된 대표사진이 아닙니다.
촬영 분석조형성·구도·빛·에디토리얼 활용을 비교합니다. 점수는 촬영 허가 여부를 뜻하지 않습니다.
마이페이지전체 아카이브, 백업, 설정 및 이 매뉴얼을 엽니다.
관리자 모드편집·사진 변경·삭제·게시 기능을 엽니다. 작업 후 ‘관리자 잠금’을 누릅니다.

2. 검색과 목록 복귀

  1. 검색창에 장소명·지역·분류·별칭·촬영 분위기를 입력합니다. 예: 벽돌 자연광 레트로.
  2. 지역·공간 유형·촬영 분위기·사진 상태 필터를 조합합니다. 결과가 없다면 검색어 수를 줄이고 필터를 ‘전체’로 되돌립니다.
  3. 장소 카드를 눌러 상세 정보를 봅니다.
  4. 상세 화면에서 ‘2.0 전체 장소 목록으로 돌아가기’를 눌러 목록으로 복귀합니다. 이전에 보던 목록 위치와 필터를 유지하도록 설계되어 있습니다.

‘맨 위로’ 버튼은 화면을 충분히 아래로 내렸을 때 나타납니다. 시작 화면이나 페이지 상단에서는 숨겨져 있을 수 있습니다.

3. 장소 상세·이미지 둘러보기·지도·즐겨찾기

  • 사진 기획 점수: 시각적 고유성, 구도 다양성, 빛·재료, 에디토리얼 활용도, 실내외 유연성을 정리한 기획 평가입니다. 출입 가능성과 허가는 별도로 확인합니다.
  • 장소 이용 정보: 공식 홈페이지·전화·주소가 표시되면 원문에서 최신 운영시간, 휴관, 예약, 비용, 주차·장비 반입 조건을 확인합니다.
  • 다른 사진 둘러보기: 장소 상세화면의 ‘다른 사진 둘러보기’는 관리자 모드 없이 사용할 수 있습니다. Google 이미지·네이버 이미지·Bing 이미지·공식 출처 링크에서 외관, 실내, 패션·인물, 건축 디테일 사진을 더 찾아 공간 전체 분위기를 살펴봅니다.
  • 장소 이미지 모아보기: 등록된 참고사진 후보가 여러 장이면 대표사진 아래에 작은 이미지 갤러리가 표시됩니다. 이미지를 누르면 원문 출처가 새 창으로 열립니다. 미리보기가 안 나오면 원문을 열어 확인하세요.
  • 지도/길찾기: 지도 보기 또는 길찾기를 선택한 뒤 네이버 지도·티맵 등을 엽니다. 건물 대표 주소와 촬영 공간 입구가 다를 수 있습니다.
  • 저장하기: 하트/저장하기로 즐겨찾기에 넣고 다시 눌러 해제합니다.
  • 매체 노출·촬영 이력: 작품명과 근거가 확인된 정보만 참고합니다. 촬영 이력이 있다는 것과 현재 대관이 가능하다는 것은 다릅니다.

4. 관리자 모드

  1. 상단 ‘관리자 모드’를 누릅니다. 모바일에서도 같은 버튼을 사용합니다.
  2. 전달받은 공통 관리자 비밀번호 2개 중 하나를 정확히 입력합니다. 대·소문자와 하이픈을 그대로 입력해야 하며, 앱에서 새 비밀번호를 등록할 수는 없습니다.
  3. 잠금이 풀리면 장소·사진 편집 도구가 활성화됩니다.
  4. 작업 후 ‘관리자 잠금’을 누릅니다. 페이지를 다시 열면 잠금 상태로 시작합니다.
보안 주의: 이 잠금은 공개 웹앱의 화면 조작을 줄이는 장치이지 서버 로그인은 아닙니다. GitHub 자료를 바꾸려면 별도의 저장소 쓰기 토큰이 필요합니다. 토큰과 비밀번호를 타인과 공유하지 마세요.

5. 새 장소 추가하기

장소 등록은 먼저 핵심 정보만 입력해도 됩니다. 장소명·지역과 실제 위치를 찾을 수 있는 정보, 참고 이미지 또는 이미지 검색어, 사진가 관점의 특징을 기록해 초안으로 저장한 뒤 GitHub 동기화·게시를 하면 됩니다. 세부 촬영 메모는 나중에 보완해도 됩니다.

A. 등록 양식 열기

  1. 관리자 모드를 엽니다.
  2. 홈의 ‘＋ 장소 신규 등록’ 또는 아카이브 관리자 패널의 ‘＋ 새 장소 등록’을 누릅니다.
  3. 새 장소 상세 화면이 열리면 기본 정보와 촬영 기획 정보를 입력합니다.

B. 기본 정보 입력

항목입력 방법
장소명·지역공식 표기와 실제 시·도를 입력합니다. 장소명이 있어야 저장할 수 있습니다.
분류·별칭예: 산업유산·벽돌 창고. 별칭은 쉼표로 구분해 중복 검색에 활용합니다.
주소·전화공식 출처로 확인된 값만 씁니다. 모르는 값은 추정하지 않습니다.
공식 홈페이지·근거 링크관리기관·설계사·공공기관 등 근거 URL을 입력합니다. 복수 링크는 쉼표로 구분합니다.
운영 상태·촬영 허가모르면 ‘미확인’으로 둡니다. 일반 관람 허용과 상업 촬영 허가는 별도입니다.
촬영·조사 메모형태·빛·재료·구도·배경의 특징과 촬영 제한을 기록합니다.

입력 후 ‘장소 정보 저장’을 누릅니다. 이 저장은 현재 기기의 임시 초안입니다.

C. 사진 기획·분류 정보 저장

‘촬영 기획·분류 정보 입력’에서 사진가 관점의 설명, 공간 유형, 시각적 강점, 추천 콘셉트, 제약 조건, 사진 잠재력 점수(0–100), 조사 우선순위(A/B/C), 지도 검색어, 출처와 추가 메모를 입력하고 ‘촬영 기획·분류 정보 저장’을 누릅니다. 쉼표로 구분하는 입력란은 쉼표를 사용합니다. 점수는 기획 평가이지 허가 가능성 점수가 아닙니다.

D. 사진과 확인 상태 추가

  1. 일반 장소 화면에서는 Google·네이버·Bing 이미지 검색과 공식 출처를 사용할 수 있습니다. 관리자 모드의 Openverse/Wikimedia Commons 자동 검색은 후보를 앱에 저장하는 보조 기능입니다.
  2. 실제 그 장소를 촬영한 사진인지 확인합니다. 다른 지점·지도 이미지·항공 사진을 일반 대표사진으로 잘못 사용하지 않습니다.
  3. ‘사진 추가/교체’에서 이미지 URL 또는 파일을 선택하고, 사진 설명·구도·장소 일치 여부·원문 링크를 입력한 뒤 ‘사진 후보 추가’를 누릅니다. 지원 사진 파일은 JPG/PNG/WebP/AVIF, 8MB 이하입니다.
  4. 대표사진은 해당 장소와 실제 공간이 맞는지 먼저 확인합니다. 이미지가 아직 없으면 검색어와 위치 정보만 저장하고 나중에 보완할 수 있습니다.
  5. 확인된 후보의 ‘대표사진으로 사용’ 또는 ‘대표사진 선택’을 누릅니다.
  6. 필수 정보와 참고 이미지를 저장한 뒤 ‘GitHub 동기화·게시’를 실행합니다. 나머지 설명은 이후 보완할 수 있습니다.
중복 방지: 먼저 기존 목록에서 장소명·별칭·주소를 검색합니다. 후보 사진이나 홈페이지가 있다는 이유만으로 추천 장소 검증이 끝난 것은 아닙니다.

6. 장소 수정·삭제

상세 화면의 ‘정보 수정’으로 편집 영역에 이동합니다. 기본 정보, 촬영 기획·분류 정보, 현장 체크리스트는 각각 별도의 저장 버튼이 있으므로 수정한 영역마다 저장해야 합니다.

‘장소 삭제’는 확인 대화상자를 거쳐 실행됩니다. 삭제 전에 JSON 백업을 내보내고 대상 장소 이름을 다시 확인하세요. 사진 후보의 ‘사진 정보 수정’, ‘이미지 주소 변경’, ‘파일로 교체’, ‘사진 삭제’도 각각 별도 작업입니다. 대표사진을 삭제하기 전 다른 사진을 대표로 지정할지 확인합니다.

7. 일반 화면 이미지 검색과 참고사진·대표사진 관리

일반 화면에서 다른 사진 찾기

  1. 장소 상세화면의 ‘다른 사진 둘러보기’를 열고 Google 이미지·네이버 이미지·Bing 이미지 중 검색할 곳을 누릅니다. 각 검색은 새 창에서 열립니다.
  2. 검색 방향을 장소·현장 전경, 패션·인물, 건축·기하학, 실내·자연광, 야외·인물 배경, 디테일·재료·그림자로 바꾸면 검색어도 함께 바뀝니다.
  3. 검색 결과의 사진을 눌러 원문에서 실제 장소와 세부 구역을 확인합니다. 이미지를 보는 것만으로 앱에 자동 저장되지는 않습니다. 앱에 후보로 등록하는 작업은 관리자 모드에서 별도로 합니다.
  4. 앱에 이미 저장된 후보는 ‘장소 이미지 모아보기’에서 여러 장을 확인할 수 있습니다. 이미지 링크를 누르면 원문 출처로 이동합니다.
검색 이미지나 갤러리 사진은 장소 분위기를 이해하기 위한 참고입니다. 사진이 공개되어 있다는 이유만으로 다운로드·재배포·상업 사용이 허가되지는 않습니다. 실제 장소 일치, 이미지 이용권, 현장 촬영 허가는 서로 별도로 확인합니다.

자동 검색은 검증이 아닙니다

자동 검색 결과는 다른 장소, 저해상도 썸네일, 권리 조건이 불명확한 사진을 포함할 수 있습니다. 검색 완료 메시지는 장소·저작권 검증 완료를 뜻하지 않습니다. 원문 링크, 실제 장소 일치와 라이선스를 확인한 뒤 후보로 저장합니다. 일반 화면에서 미리보기나 검색 결과가 보이더라도 대표사진 승인이나 상업 이용 허가가 된 것은 아닙니다.

이미지 URL과 사진 파일

  • URL: 인터넷 이미지 주소를 참조합니다. 원문이 삭제되거나 직접 이미지 주소가 막히면 표시되지 않을 수 있습니다. URL만 등록한다고 파일이 저장소로 복사되는 것은 아닙니다.
  • 파일: 선택한 사진 파일은 먼저 현재 브라우저의 임시 보관에 들어갑니다. 대표/참고 사진으로 선택된 파일은 GitHub 게시 시 업로드 대상이 될 수 있습니다. 게시 완료 후 실제 표시 여부를 확인합니다.
  • 대표사진: 장소를 직접 보여주고 구도·조형성이 있는 이미지를 고릅니다. 장소 일치가 미확인인 사진은 대표로 확정하지 않습니다.

‘사진을 불러올 수 없습니다’일 때

  1. 원문 페이지에서 사진 내용과 실제 장소를 대조합니다.
  2. 원문 삭제·접근 차단·직접 링크 차단 여부를 확인합니다.
  3. 다른 공식 출처나 권리 조건이 분명한 사진을 검색합니다.
  4. 대체 사진이 없으면 다른 장소 사진으로 채우지 말고 미확인 상태로 둡니다.
  5. 파일 게시 후 저장소의 v2/assets/places/ 경로와 카탈로그 경로가 일치하는지 확인합니다.
사진 표시, 실제 장소와 일치, 사진 재사용 권리, 장소에서의 상업 촬영 허가 — 이 네 가지는 서로 다릅니다.

8. 현장 촬영 체크리스트

9. 백업·복원·GitHub 게시

수정 전 백업

  1. 관리자 도구에서 ‘안전 백업 내보내기’ 또는 ‘백업 내보내기’를 누릅니다.
  2. 다운로드한 JSON을 PC의 별도 폴더에도 보관합니다. 파일명에 날짜를 넣어 이전 상태와 구분합니다.
  3. 장소·사진을 많이 수정한 뒤에도 새 이름으로 추가 백업을 저장합니다.

백업 가져오기

‘JSON 백업 가져오기’는 현재 기기의 작업 카탈로그를 통째로 바꿀 수 있습니다. 가져오기 전에 현재 상태도 먼저 내보내세요. 오래된 기기 백업을 최신 공통 자료에 무심코 가져오면 다른 기기에서 게시한 수정사항을 덮어쓸 수 있으므로, 두 파일을 자동 병합하는 기능이라고 생각하면 안 됩니다.

GitHub에 게시하기

  1. 백업 후 관리자 도구에서 ‘GitHub 동기화·게시’를 누릅니다.
  2. 저장소 casio8000/FRAME_ATLAS에만 Contents 읽기/쓰기 권한을 준 Fine-grained Personal Access Token을 입력합니다.
  3. ‘게시 시작’을 누르고 완료 또는 오류 메시지를 확인합니다. 게시 중 페이지를 닫거나 새로고침하지 마세요.
  4. 현재 앱은 카탈로그 파일을 GitHub의 main 브랜치에 직접 게시합니다. 장소 데이터는 v2/data/places.json에 기록되고, 업로드 대상으로 선택된 사진 파일은 v2/assets/places/ 아래에 저장됩니다.
  5. GitHub Actions에서 Pages 배포 성공을 확인하고 PC와 iPhone에서 2.0 주소를 다시 엽니다.
동시 편집 금지: PC와 iPhone에서 각각 오래된 작업 초안을 편집한 뒤 양쪽에서 게시하면, 나중에 게시한 초안이 다른 기기의 새로운 수정사항을 덮어쓸 수 있습니다. 현재는 모든 필드의 변경 이력을 비교해 안전하게 자동 병합하는 완전한 동기화 기능이 아닙니다. 한 번에 한 기기만 편집·게시하도록 운영하세요.

사진 파일 게시 조건

인터넷 이미지 URL은 주소를 참조할 뿐 저장소에 파일이 복사되는 것이 아닙니다. 기기에서 선택한 사진 파일도 처음에는 해당 브라우저의 임시 보관소에 있습니다. 현재 게시 과정은 대표사진·기본 참고사진으로 선택되었거나 승인된 파일을 업로드 대상으로 처리합니다. 게시 완료 후 실제 파일 경로와 앱의 사진 표시를 확인하세요.

토큰과 초기화 안전

토큰은 저장소에 보관하지 않으며 다시 게시할 때 재입력이 필요할 수 있습니다. ‘배포된 기본자료 다시 읽기’는 이 기기의 미게시 초안을 지울 수 있습니다. 실행 전 반드시 JSON 백업을 내보내고, 새 공통 자료로 바꾸려는 것이 맞는지 확인하세요.

11. PC·모바일 데이터 동기화 — 간편 병합 방식

권장 방식: PC와 모바일에서 각각 장소를 등록하고, 마지막에 ‘GitHub 동기화·게시’를 누릅니다. 각 기기에서 작성한 초안은 그 기기 안에 저장되며, 버튼을 누르면 GitHub 최신 자료와 이 기기 변경분을 합쳐 공통 자료로 게시합니다.

동기화는 이렇게 진행됩니다

  1. 각 기기에서 장소 등록·수정: 장소명·지역·위치 정보와 간단한 사진가 관점 설명부터 저장합니다. 참고 이미지는 실제 장소와 맞는지 확인한 범위에서 넣으면 됩니다. 점수·비용·세부 체크리스트를 완벽하게 채우지 않아도 먼저 등록할 수 있습니다.
  2. 관리자 모드 → GitHub 동기화·게시: 게시 직전에 앱이 GitHub의 최신 카탈로그를 다시 읽습니다. PC가 추가한 장소가 모바일에 없더라도, 모바일에서 새로 추가한 다른 ID의 장소와 함께 병합해 게시합니다.
  3. 서로 다른 항목 수정은 함께 유지: 예를 들어 PC에서 장소 주소를 수정하고 모바일에서 같은 장소의 촬영 메모를 수정했다면, 서로 다른 필드이므로 가능한 범위에서 합칩니다. 새로 추가한 장소도 ID가 다르면 합쳐집니다.
  4. 같은 항목을 양쪽에서 다르게 수정하면 중지: 같은 장소의 같은 필드가 서로 다르면 앱이 덮어쓰지 않고 충돌을 알려줍니다. 메시지에 나온 장소를 한 기기에서 정리한 뒤 다시 동기화합니다.
  5. 최신 배포 확인: 동기화·게시 완료 후 GitHub Actions의 Pages 배포가 성공하면 다른 기기에서 2.0 페이지를 새로고침합니다. 캐시나 오래된 로컬 초안이 남으면 이전 화면이 보일 수 있습니다.

처음 한 번만 주의할 점 — 예전 초안

이전에 사용하던 기기의 초안에는 병합 기준 시점이 없을 수 있습니다. 처음 동기화하기 전에는 관리자 도구에서 JSON 백업을 내보내세요. 앱은 오래된 초안의 새 장소와 더 최신으로 보이는 변경을 보존하려고 하며, 다른 기기의 최신 내용과 확실히 구별할 수 없는 충돌은 게시를 중지합니다. 기준이 없던 초안의 삭제는 안전을 위해 첫 동기화에서 자동 적용하지 않습니다. 첫 동기화가 성공하면 이후에는 새 기준본을 저장해 변경을 비교합니다.

토큰을 기기에 기억시키기

‘GitHub 동기화·게시’ 창에서 ‘이 기기에 GitHub 토큰 기억하기’를 선택하면 그 기기의 브라우저에만 저장되어 다음 게시 때 다시 입력하지 않아도 됩니다. PC에 저장해도 iPhone으로 복사되지는 않으므로 각 기기에서 필요하면 한 번씩 입력합니다. 본인만 쓰는 기기에서만 체크하고 공용 컴퓨터에서는 체크하지 마세요. 토큰 권한은 casio8000/FRAME_ATLAS 저장소의 Contents 읽기/쓰기만으로 제한하는 것이 좋습니다.

사진 파일의 기기 차이

이미지 URL과 이미지 후보 정보는 병합할 수 있지만, 아직 게시하지 않은 파일 자체는 원래 선택한 기기의 임시 보관소에 있습니다. 해당 파일을 게시하려면 파일을 선택했던 기기에서 동기화·게시하거나, 다른 기기에서 파일을 다시 선택해야 합니다.

추가·수정·삭제 데이터 관리 원칙

작업권장 방식
새 장소 추가장소명·지역·주소/지도 검색어와 간단한 시각적 특징부터 등록하고, 상세 설명은 차츰 채웁니다. 먼저 이름과 주소로 중복만 확인합니다.
기존 장소 수정수정한 필드만 바꾼 뒤 저장합니다. 각 영역의 저장 버튼은 해당 기기에 초안을 기록하고, GitHub 동기화·게시가 공통 원본을 갱신합니다.
대표·참고사진 수정웹에서 여러 이미지를 둘러보고, 실제 장소와 이미지가 맞는지 중심으로 고릅니다. 출처와 사진 설명은 나중에 보완할 수 있습니다.
장소 삭제삭제는 다른 기기에도 반영되는 변경입니다. 병합 기준이 이미 있는 기기에서 삭제하면 변경사항으로 기록됩니다. 이전 초안의 첫 동기화에서 삭제가 무시된 경우, 첫 게시 이후 최신 자료를 다시 읽고 삭제를 다시 실행하세요.
백업대량 추가·수정 전에 JSON 백업을 권장합니다. 백업은 복구용이며, 오래된 JSON을 최신 카탈로그 위에 통째로 가져오면 안 됩니다.
중요: 앱은 PC와 모바일 사이의 서로 다른 장소·필드 수정 병합을 지원하도록 개선되었습니다. 네트워크/권한 오류나 같은 필드 충돌 시 게시가 중지될 수 있습니다. 중요한 장소 묶음 작업 전후에는 백업을 보관하세요.

11. 문제 해결

PC에서 매뉴얼 ‘맨 위로’·‘닫기 ×’가 안 보임

이 개정판은 PC에서 오른쪽 위, 작은 화면에서는 오른쪽 아래에 버튼을 고정합니다. 매뉴얼 최신판 다시 열기를 사용합니다. 닫기는 새 탭을 닫을 수 있으면 닫고, 그렇지 않으면 이전 화면 또는 앱으로 돌아갑니다.

관리자 비밀번호 불일치

  • 예전에 이 PC에서 자체 등록했던 비밀번호는 이전 방식일 수 있습니다. 현재는 전달받은 공통 비밀번호 두 개만 사용합니다.
  • 대·소문자와 하이픈을 확인하고 앞뒤 공백을 제거합니다. 새로고침한 뒤 다시 입력합니다.

수정이 모바일에서 안 보임

  1. 작업한 기기에서 ‘임시저장’인지 ‘게시 완료’인지 확인합니다.
  2. 백업 후 GitHub에 게시합니다.
  3. Actions에서 Pages 배포 성공 여부를 확인합니다.
  4. PC는 Ctrl+F5, 모바일은 홈 화면 아이콘 대신 브라우저에서 직접 2.0 주소를 엽니다.

목록으로 돌아갈 때 엉뚱한 위치로 이동

장소 상세 화면의 ‘2.0 전체 장소 목록으로 돌아가기’를 누릅니다. 문제가 지속되면 현재 주소에 /v2/index.html이 있는지 확인하고 문제 화면을 캡처합니다.

게시 실패 또는 사진 파일을 찾지 못함

오류 문구를 기록하고 토큰 권한, 저장소 이름, 배포 오류를 확인합니다. 파일이 기기 임시 보관에만 있으면 원래 기기에서 다시 선택해야 할 수 있습니다. 성공 메시지만 믿지 말고 실제 사진을 열어 확인합니다.

12. 장소 선정 원칙

  • 관광 인지도보다 조형적 고유성, 구도 다양성, 빛·재료, 패션·인물·에디토리얼 활용도, 실내외 유연성을 평가합니다.
  • 대형 스튜디오·공연장·산업유산·현대건축·미술관·도시 질감·자연과 인공 구조의 조합 등 촬영 결과를 차별화할 수 있는 유형을 찾습니다.
  • 장소 존재 여부, 사진의 실제 장소 일치, 사진 사용권, 상업 촬영 허가는 각각 확인합니다.
  • 운영 종료·휴관·출입 제한 또는 사진 불일치가 확인된 장소는 추천에서 보류합니다. 후보 사진이 있다는 이유로 검증 완료로 표시하지 않습니다.
